# 🚀 Ultimate Postman Guide for Liquid Media API

This guide will walk you through how to test and debug your backend endpoints using **Postman**.

---

## 1. Prerequisites
*   **Postman Installed:** Download from [postman.com](https://www.postman.com/downloads/).
*   **Backend Running:** Ensure your server is running (usually `npm start` or `node server.js`).
*   **Base URL:** 
    *   **Local:** `http://localhost:8080`
    *   **Production:** `https://your-app.railway.app` (Replace with your actual Railway URL)

---

## 2. Setting Up an Environment (Best Practice)
Instead of typing `http://localhost:8080` every time, use **Environments**:
1. Click **Environments** on the left sidebar in Postman.
2. Click **+** (Create New Environment).
3. Name it `Liquid-Local`.
4. Add a variable:
   *   **Variable:** `base_url`
   *   **Initial Value:** `http://localhost:8080`
5. Click **Save** (Top Right).
6. Select `Liquid-Local` from the environment dropdown in the top-right corner of Postman.

## 3. Testing the Endpoints

### ✅ 1. Health Check
*   **Method:** `GET`
*   **URL:** `{{base_url}}/health`
*   **Description:** Verifies if the server is alive and responding.
*   **Expected Response:**
    ```json
    {
        "status": "ok",
        "timestamp": "2026-04-02T..."
    }
    ```

### 🐞 2. Debug Information
*   **Method:** `GET`
*   **URL:** `{{base_url}}/api/debug`
*   **Description:** This endpoint reports the status of `yt-dlp` and the server environment variables. Great for troubleshooting.
*   **Expected Response:** JSON containing `ytdlpVersion`, `node`, and `platform` details.

### 🔍 3. Extract Media Info (Core Logic)
*   **Method:** `POST`
*   **URL:** `{{base_url}}/api/extract`
*   **Headers:** `Content-Type: application/json`
*   **Body:** Select **raw** and set the format to **JSON**.
*   **Input JSON:**
    ```json
    {
        "url": "https://www.youtube.com/watch?v=dQw4w9WgXcQ"
    }
    ```
*   **Description:** This simulates your frontend sending a link for processing. 
*   **Expected Response:** A `success` object with a list of `formats`. Each format contains a `url` that points back to your proxy download endpoint.

### 📥 4. Proxy Download (Direct Stream)
*   **Method:** `GET`
*   **URL:** `{{base_url}}/api/download?url=YOUR_LINK&filename=test.mp3`
*   **Query Params:**
    *   `url`: Use a video URL or a direct media link.
    *   `filename`: The name you want the downloaded file to have.
*   **Description:** Tests the streaming/download logic. 
*   **Postman Tip:** In Postman, click the arrow next to the **"Send"** button and select **"Send and Download"** to actually save the file to your computer and check if it plays correctly.

## 4. Pro Tips for Testing

### 💾 Status Codes to Watch For
*   **`200 OK`**: Everything is working perfectly.
*   **`400 Bad Request`**: You likely forgot to include the `url` in the request body/params.
*   **`500 Internal Server Error`**: Something crashed on the backend (check your terminal logs for the error message).

### ⚡ Quick Extraction Test Script
You can add this to the **"Tests"** tab of your `POST /api/extract` request in Postman. It will check if the result is successful automatically:
```javascript
pm.test("Status code is 200", function () {
    pm.response.to.have.status(200);
});

pm.test("Should return success status", function () {
    var jsonData = pm.response.json();
    pm.expect(jsonData.status).to.eql("success");
});
```

### 💡 Common Issues
1. **Empty Formats:** If you get `formats: []`, it means `yt-dlp` reached a bot-protection wall or the link is private.
2. **Infinite Loading:** Ensure your server is actually running on the port you are testing (Default: 8080).
3. **CORS:** Postman does not enforce CORS, so if a request works in Postman but fails in your Browser, you need to check the `corsOptions` in your `server.js`.
